\section{Testing Results}
\label{sec:results}

\subsection{Test Environment and Method}
\label{sec:test-method}

All measurements were taken on macOS 27.0.1 (build 26A434), an Apple M3 with
16\,GiB of memory, CMake 4.4.3 (Unix Makefiles), and Apple clang 21.0.0. The
code is C++17, compiled with \code{-Wall -Wextra} in Release mode
(\code{-O3 -DNDEBUG}). Catch2 v3 is linked only into the tests; the
\code{build/mse} binary (329,136 bytes) links only system libraries.

CTest runs 18 tests: 8 Catch2 unit-test executables (46 \code{TEST\_CASE}s and
85,155 assertions), 2 corpus smoke tests, and 8 independent cross-check tests.
All 18 pass in 40.90 seconds. The cross-checks are not a second run of the same
code: \code{tools/check\_wordcount.py} re-tokenizes and re-stems the corpus to
produce the expected CSV, \code{tools/brute\_force.py} scans the text layer and
independently parses the binary index, and \code{tools/check\_phrases.py}
brute-forces sampled phrases on the Python token stream. The golden sample is
the four-document example from the course notes, checked posting by posting.

The test-case table below is a representative subset. It records the purpose,
expected result, actual behavior, root cause for corrected defects, and current
status of each case. The status vocabulary is deliberately small: \emph{Pass},
\emph{Corrected}, and \emph{Pending}.

The (0.40,0.93) setting derives 39 words and overlaps the static list in 35.
The differences are four explainable pairs: the automatic list adds the archaic
function words \code{hath}, \code{o}, \code{thee}, and \code{thou}, while the
static list adds \code{more}, \code{or}, \code{than}, and \code{their}, which
also serve as comparison and conjunction words. The former are wide and flat in
the source text; the latter are a semantic judgement by the curators. The
three-feature rule turns ``is this a stop word?'' from a manual decision into a
recomputable test, and the result differs from the manual table in only four
words, each of which can be explained. Changing the threshold changes only the
strictness (9/23/39/50 words), not the structure of the rule. All four output
files carry a provenance header and no timestamp, so a parameter change can be
rerun and compared directly.

words, and proper nouns and marks the 0.93 threshold.

A word query returns the document IDs and titles that contain the term. Results
are ordered deterministically by matched-term count, total term frequency, and
document ID. With \code{--pretty}, the program reruns the text pipeline and
prints the source line containing the match.

A phrase query verifies that the terms occur consecutively in the
stop-word-filtered token stream; it is not enough to intersect the posting
lists. \code{good night} returns 23 documents, and only documents in which the
two terms are adjacent are kept. Because positions are defined on the filtered
stream, \code{my} in \code{my lord} occupies no position, and the system
effectively executes a word query for \code{lord}. A phrase made only of stop
words has no locatable term and returns nothing.

A Boolean query requires all query terms by default, so \code{king queen}
returns 33 documents. With \code{--min-match 1}, either term is enough and the
result rises to 43. When a query is empty, the program distinguishes ``stop
word not in the index'' from ``term not in the dictionary'' instead of
collapsing both cases into one message.

\subsection{Threshold Experiment Results}
\label{sec:threshold}

All four parameters act only at query time. With every parameter off, the same
query gives the baseline. The experiment changes one parameter at a time over
15 queries that cover high-, medium-, and low-frequency words, proper nouns,
ordinary phrases, phrases containing stop words, Boolean queries, and stop
words. Every query is tested with five \code{max-df} levels, four
\code{min-df} levels, and three \code{top-x} levels; the minimum-match count
applies only to the Boolean queries \code{king queen} and \code{sweet sword
moon}, with three levels. This gives
$15+15\times(5+4+3)+2\times3=201$ measurements. Each record stores the result
count, the Jaccard similarity to the baseline, the number of explanation
messages, and the elapsed time, all on the same formal index.
Figure~\ref{fig:threshold} shows the effect of each parameter on the number of
returned documents.

The maximum and minimum document-frequency thresholds filter query terms, not
result documents. A word query has only one term, so removing that term makes
the result zero. \code{love} has a df ratio of 0.7077, so at the 0.7 level the
result drops from 138 to 0; \code{sweet} has a ratio of 0.4615 and also drops to
zero at the 0.3 level.

A multi-term query can lose a constraint before it loses results.
\code{sweet sword moon} has a baseline of 30 documents. With \code{--min-df 50},
\code{sword} (df 37) and \code{moon} (df 35) are removed, leaving \code{sweet};
the three-term conjunction degenerates into a word query and the result rises
to 90. This is not an increase in precision: the term filter has changed the
meaning of the query.

The minimum-match count controls the Boolean condition on the result side.
$k=1$ is a union, $k=2$ requires at least two terms, and $k=3$ requires all
three; when $k$ exceeds the number of searchable terms, the program clamps it to
that number. Result truncation is simpler: after ranking, only the first $x$
documents are kept, so \code{love} returns 5, 10, and 20 documents without
changing their relative order.

Phrases and stop words provide the two boundary cases. A phrase query bypasses
the maximum and minimum df thresholds, so \code{king richard} stays at 7
documents at every level; removing either term would destroy the phrase. Stop
words never enter the index, so \code{the} and \code{of} return zero at every
threshold. Of the 201 measurements, 23 have Jaccard zero; each occurs after all
effective query terms have been removed, and the explanation records the
corresponding terms and the reason. No empty result is unexplained.

\finding{The four thresholds are not the same kind of ``tightening.'' The
maximum and minimum df thresholds change which terms participate,
\code{min-match} changes the Boolean condition, and \code{top-x} only changes
the output range. Removing terms can make a result empty or, by weakening a
conjunction, larger.}

\subsection{Summary of Testing Results}
\label{sec:results-summary}

The required tasks pass their correctness checks: the tokenizer, stemmer,
dictionary, index, and query tests are green, and independent Python
implementations agree with the C++ output on the word-count CSV, the full
posting tables, and 303 phrase queries. The four thresholds behave as
specified, including the counterintuitive case in which filtering query terms
