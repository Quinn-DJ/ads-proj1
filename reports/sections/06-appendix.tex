\subsection{索引 v1 布局与 v2 差异}

所有整数为小端；字符串为 u32 字节长度前缀 + 原始字节。v1 顺序布局如下：

\begin{lstlisting}[style=cli]
header : magic "MSE1" | version u32 | flags u32 | docCount u32 |
         termCount u32 | tokenCount u64                 (28 bytes)
doc    : docID u32 | keptTokens u32 | titleLen u32 | title[...]   (12+len)
term   : termLen u32 | term[...] | df u32 | tfTotal u64 |
         blockOffset u64 | blockBytes u32                (28+len)
block  : df x (docID u32, tf u32), then sum(tf) x position u32
         blockBytes = 8*df + 4*sum(tf)
\end{lstlisting}

\code{flags} 第 0 位置停用词过滤、第 1 位置词干化，查询侧据此重放同一规范化管线；
term 表严格升序，docID 稠密 1..N，posting 内 docID 严格递增、tf 等于其位置数，这些
不变量在加载后由 \code{validateIndex()} 逐条校验。v2 的头、doc 表、term 表与 v1 相同，
仅 \code{version}$\,=2$，把每个 postings 块换成"差分量 + 字节对齐变长码"：每条 posting
依次写 docID 差（块内从 0 起，$\ge1$）、tf、tf 个位置增量（posting 内从 0 起，$\ge0$）；
变长码首字节高 2 位给出总长，载荷 6/14/22/30 位（\code{01}/\code{10}/\code{11}/\code{00}
分别为 1/2/3/4 字节），小端序。

\subsection{磁盘 B+ 树 词典 sidecar}

sidecar 是 4\,KiB 页文件（页大小可配置），第 0 页为头页、其后每页一个树节点，整数
小端；键是变长字符串，扇出由字节预算决定，叶页用 \code{nextLeaf} 串成有序链。

\begin{lstlisting}[style=cli]
page 0 (header) : magic "BPT1" | version u32 | pageSize u32 |
                  pageCount u32 | rootId u32 | height u32 |
                  leafCount u64 | keyCount u64
page i+1        : leaf u8 | keyCount u16 | nextLeaf u32 |
                  leaf  : value u64[count] | blob[count]
                  inner : child u32[count+1] | blob[count]
blob            : length u8 | bytes
value           : (posting blockOffset << 21) | blockBytes   (21-bit length)
\end{lstlisting}

查询时由 B+ 树定位 posting 块，无需加载完整 term 表。I1--I5 由
\code{validate()} 校验；写文件采用 bulk-load，索引重建后 sidecar 同步重建。
% 格式规格来自 include/bptree.hpp 与 src/bptree.cpp；不涉及测量数字
